New on 2026-10-25

  • E fast and E slow: the cause of the two ISR → thread modes is known. The slow mode has one SysTick reprogram (about 310 cycles) in the slice reset. A test confirmed the prediction: the share of the fast mode follows only the poll period of the main thread (20 % at 100 ms, 2 % at 1000 ms).
  • F: with timers, each slice reset walks the timeout list with interrupts masked. ISR → thread p50 goes from 1686 to 4192 cycles with 256 timers. WHEEL gives 1429.
  • G and G2: with 256 timers, most of the IRQ tail is the SysTick ISR body, because SysTick has the same priority as the device IRQ. With SysTick one level lower, the p99.99 falls from 25888 to 6912 cycles.
  • H fast and H slow: thread → thread has two SysTick reprograms per switch in the slow mode: 668 of the 2047 cycles of the slow mode.
  • I: each reprogram loses some cycles of the kernel clock: 8.0 or 9.7 cycles per wake. With 256 timers, the clock also loses whole reloads (4661 ppm).
  • E-sw fast and E-sw slow: with USE_SWITCH=y there is no PendSV on Cortex-M. The switch runs at the end of the ISR in handler mode. The two modes stay (one reprogram), but each wake costs about 250 to 280 cycles more, and the masked section of the switch is longer.
  • H-sw fast and H-sw slow: with USE_SWITCH=y a thread switch resets the slice twice (kswap.h:130 after update_cache()). The slow mode then programs SysTick four times per switch: the mode distance grows from about 650 to about 1300 cycles on both trees. We predicted this from the code before the run.
  • Method: the place of the code in flash changes the results. Single builds of the same code differ by up to about 190 cycles. Do not compare single builds when the difference is small.

How to read the diagrams

The lanes come in three groups. Core: the hardware, then the interrupt mask (PRIMASK, BASEPRI). ISRs: from the highest to the lowest priority. Threads: from the highest to the lowest priority. The chip next to a lane name gives the priority. ISR numbers are IRQ_CONNECT() numbers (0 is the highest kernel priority); ZLI is above all kernel IRQs, and PendSV has the lowest priority. Thread numbers are Zephyr thread priorities (a lower number runs first). Joined chips mark lanes with the same priority: these contexts cannot preempt each other.

The "arch" tag of a card gives the arch interface. With the default USE_SWITCH=n, a thread switch runs in PendSV. With USE_SWITCH=y there is no PendSV: a switch from an ISR runs at the end of the ISR, and a switch from a thread is inline code in z_swap().

The order of the steps comes from the Zephyr code (paths in the cards). The total between the edge and the time stamp is measured. The split inside a total is an estimate, unless the step has a solid outline. The distributions do not record what ran at each sample, so a diagram is one typical sample of its mode.
